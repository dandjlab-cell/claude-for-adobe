## What this project is

A public, MIT-licensed Adobe Premiere Pro CEP panel ("Claude for Premiere") that runs the user's own Claude Code (or Codex) inside Premiere. The editor clicks a folder or clips, says what they want, and the agent inspects footage, transcribes, cuts silences, fillers and repeated takes, reframes, lays b-roll, organizes bins, and makes captions, all through deterministic panel tools that print CHECK lines and keep a duplicate-sequence safety net. Users install a zip; the panel self-updates from GitHub Releases. Latest public release: **0.1.77 (2026-09-07)**.

What this says for the simulator, from ONE data point (do not over-fit): the lift is **not** a naive 2x multiply — midtones scale ~1.27 in encoded 8-bit while p99 scales only 1.12 and **nothing clipped** (0% at 255 before AND after), i.e. Lumetri rolls the highlights off with a shoulder rather than clipping; the floor lifts proportionally more (1.83 at min, but 8-bit codes 12→22 are quantisation-noisy); and exposure is not saturation-neutral in the measured output (median 24→30). A midtone encoded ratio of 1.27 is ~1.7x in linear light at gamma 2.2, i.e. nearer +0.76 stops than +1.00 — so "Exposure 1" does not map to exactly one stop in this 8-bit Rec.709 readout (or the BRAW/sequence transfer is not plain gamma 2.2). **Next before writing any sim math: a calibration sweep** — same frame, Exposure ∈ {-2, -1, -0.5, 0, 0.5, 1, 2}, measure each, then fit the transfer curve including the shoulder. The loop is cheap enough to do it in one prompt: each `scopes` call took 0.7-0.8 s and the write 0.8 s.

**Premiere's Exposure is asymmetric.** Downwards it is a clean gain: every percentile moves by one ratio, matching a gamma-2.4 stop to the third digit. Upwards it is a tone mapping that protects highlights: at +1 the shadows take the full stop (1.355) while the top barely moves (1.081) — which is why nothing clipped until +2 (and then blue first, 0.65%). **No static curve reproduces both directions.** Two fits were tried and both failed badly (Reinhard shoulder in linear: rms 4.3 and predictions over 100; soft-knee in display space: rms 5.0 with the optimiser pinned at every grid edge). Trying to reimplement Adobe's colour science offline is a research project, and a `scopes` call measures the real thing in under a second.

**So: no simulator. Measure a small bracket in Premiere and interpolate** — exact by construction (it is Premiere's own render), no source decoding, no per-version recalibration. `src/grade_solve.cjs` + `test/grade_solve.test.cjs` land this, with the sweep as the test fixture: `predictStat` (what a reading would be at a value) and `solveFor` (the value that hits a target). Interpolating in log(stat) is worth 0.3% against 1.5% for a straight line. Measured ceilings, all asserted by the tests: leave-one-out stat prediction is 0.2-1.1% typical and 4.6% worst (p99/max at the bend); a solved parameter lands within 0.24 of a stop worst case over a deliberately doubled bracket; extrapolating past the readings costs 3-8%, so it is refused with a `measureAt` telling the caller where to measure next. **A saturated statistic is reported `reliable: false` rather than answered confidently** — once highlights pile up, `max` moves 3% per stop against the median's 25%, so the agent must steer on the median instead. That flag is the module's main safety feature.

What survives of the offline plan: `src/source_frame.cjs` (decode a source frame outside Premiere) is still useful for analysis that must not touch Premiere at all, but it is NOT needed for grading, and the Blackmagic SDK BRAW path is no longer on the critical path.
